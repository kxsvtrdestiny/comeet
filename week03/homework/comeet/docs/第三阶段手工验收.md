# 第三阶段 Windows 双账号人工验收

前两阶段已经验收通过，无需重复其 8 项清单。本阶段不测试音视频或 AI。源码更新时保留 server/.env、server/data，不清空数据库。

## 启动：终端 A（后端 PowerShell，保持开启）

先在原后端终端 Ctrl+C。将新版 comeet 内部源码覆盖到原位置，保留 .env/data，然后执行：

```powershell
cd D:\comeet-stage1-review\week03\homework\comeet\server
$env:GOPROXY = "https://goproxy.cn,direct"
go mod download
go run ./cmd/server -env-file .env -init-env
go run ./cmd/server -env-file .env
```

看到 server_start、stage=3 即保持运行；003 迁移自动应用。已有有效 JWT 密钥不会重新生成。

## 启动：终端 B（另开 PowerShell，前端，保持开启）

先停止原前端，再执行：

```powershell
cd D:\comeet-stage1-review\week03\homework\comeet\web
npm.cmd ci
npm.cmd run dev
```

浏览器打开 **http://localhost:5173**，不要混用 127.0.0.1（Origin 白名单必须匹配）。A 用 Chrome 普通窗口，B 用 Edge 或独立隐私窗口，各自登录自己的账号。普通复制标签不等于独立账号。

## 八项验收

1. **正式入会与成员**：A 创建会议、记下会议号，在准备页点击进入；B 查询该号进入。两端都显示两名真实成员，自己的“本人”及 A 的“主持人”正确。仅打开准备页不增加成员，不申请摄像头/麦克风权限。
2. **双向聊天**：分别发送不同文本，两端立即收到且只有一条；发送 `<script>文字</script>` 应原样显示，不能执行脚本。刷新 B，消息仍在、成员不重复。消息超过 50 条时点击加载更早消息，顺序正确。自动检查已经覆盖 105 条分页，不要求人工输入上百条。
3. **重复入会保护**：复制 A 当前会议标签；应提示会话已在其他标签使用，原 A 仍能与 B 聊天。关闭复制标签不会使原 A 离会。
4. **主动离会与重入**：B 点击“离开会议”，A 成员列表移除 B；B 从工作台/会议号重新进入，只有一名 B。A 个人离开不结束会议，B 仍可使用会议；A 可重新加入。
5. **短断线恢复**：B 按 F12 → Network/网络，将 No throttling 改成 Offline；A 保持在线发送 2–3 条不同消息。约 10 秒后将 B 改回 No throttling（确保小于 45 秒）。B 自动恢复成员和漏消息，消息无重复，恢复完成后可继续聊天。别在 A 也设离线。
6. **宽限到期**：再次只将 B 设 Offline，等待超过 45 秒，A 最终不再显示 B 在线。B 恢复网络后应停止无限重试，按“重新加入”恢复；成员不重复。完成后把 Network 恢复 No throttling。
7. **后端重启**：A/B 均保持会议页，回到后端终端 A 按 Ctrl+C，随即在同一目录执行 `go run ./cmd/server -env-file .env`，在 45 秒内启动成功。前端终端 B 和浏览器不关闭；两端应自动恢复，原聊天保留、成员不重复，互发新消息成功。不要运行初始化清库或修改 JWT_SECRET；停机超过宽限时按重新加入处理。
8. **界面与诊断**：工作台无“开发环境状态”面板，左侧“设置 → 服务状态”能读取真实后端，stage=3/schemaVersion=003_realtime_chat.sql；手机宽度下成员/聊天和离会按钮可操作，无横向溢出。媒体/共享按钮仍禁用，无新增宣传标语。

```powershell

cd D:\comeet-stage1-review\week03\homework\comeet\web
```

Go 测试使用临时 SQLite，不改运行数据库；最后无输出的 go vet 表示通过。云端已执行 race，不要求 Windows 安装 C 编译器。可选浏览器自动回归（需要终端 A/B 运行，会创建测试账号和会议）：在 web 目录执行 `npx.cmd playwright install chromium`，再执行 `npm.cmd run test:e2e`。
