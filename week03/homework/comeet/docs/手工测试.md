# 第四阶段双账号音视频人工验收

前三阶段已通过，不要求重复其清单。第四阶段真实音视频仍待验证；以下使用Windows本机localhost和用户自行配置的LiveKit。

## 终端与地址

1. 原前后端窗口Ctrl+C。新版源码覆盖旧comeet，保留server/.env及server/data。
2. 记事本打开 `D:comeet-stage1-reviewweek03homeworkcomeetserver.env`，填LiveKit四项，详情见README/LiveKit.md；不要发密钥。
3. 后端终端A（PowerShell）：

```powershell
cd D:comeet-stage1-reviewweek03homeworkcomeetserver
$env:GOPROXY = "https://goproxy.cn,direct"
go mod download
go run ./cmd/server -env-file .env -init-env
go run ./cmd/server -env-file .env
```

4. 另开前端终端B（PowerShell）：

```powershell
cd D:comeet-stage1-reviewweek03homeworkcomeetweb
npm.cmd ci
npm.cmd run dev
```

5. 浏览器 **http://localhost:5173**。A用Chrome，B用Edge/独立隐私窗口，分别登录，戴耳机。A创建会议，B输入相同会议号，停在准备页。检查设置→服务状态stage=4、schemaVersion=003_realtime_chat.sql、媒体已配置；这只表示形式完整，不代表媒体可达。

## 逐项人工检查（记录通过/失败）

1. **独立设备**：准备页默认不采集，开启摄像头出现本人预览；不开麦时无麦克风采集。再开启麦克风，说话电平变化；关摄像头不影响麦克风，关麦不影响视频。选择其他设备后画面/声音源真正变化，关闭状态切换设备不自动开启。
2. **输出与错误**：点击扬声器试听，约1.5秒停止，也能主动停止；支持时切换扬声器且听到实际输出变化，不支持时应说明使用系统默认。拒绝摄像头权限时有明确提示，麦克风仍能使用；权限恢复后重新开启。无设备/被程序占用时按实际条件检查提示，可仅聊天。不能模拟的物理错误记录“待验证”。
3. **双账号音视频**：两端准备好后点击进入，业务/媒体均已连接，两名成员正确。相互看到不同的真实摄像头画面、听到对方声音，本人视频不回放本人声音；一个人说话只能听到一次。准备页轨道已释放，不应出现两套采集。
4. **开关与宫格**：会议底部独立关闭/开启麦克风与摄像头，远端相应变化，主持人/本人标识不丢；打开“音视频设置”切换输入/输出（关闭状态不能被自动开启）。多次切换/刷新后无重复成员、视频或重音；窄屏仍能聊天、操作离会。
5. **自动播放与仅聊天**：若浏览器阻止声音，点击“启用声音”后应能播放；只聊天的B不开本机采集，聊天仍可收发，也可接收其他人的媒体。暂时清空LiveKit四项并重启后端时，新进入会议提示未配置但聊天可用；测完恢复配置并重启。已有连接测试前先正常离会。
6. **分别重连**：只让B的浏览器Network→Offline约10秒后恢复No throttling，观察业务/媒体分别恢复、成员不重复、消息补齐，音视频恢复后无重音。媒体无法恢复时设置中重试，不影响文字聊天。不同网络/Wi-Fi与手机热点测试需HTTPS正确配置；未实际操作就记待验证。
7. **完整释放**：A点底部离会，摄像头指示灯/浏览器采集标记停止，B移除A且无A声音。重新加入后测试顶部返回工作台、浏览器后退、刷新、关闭标签、登录过期/退出路径；不应残留音频、设备占用或后台采集。准备页返回工作台也应释放电平AudioContext、摄像头和试听。
8. **硬件与协商待测项**：实际拔插设备应刷新列表并提示断开，不自动打开另一设备。真实2–6人宫格、弱网自适应与Simulcast三层须实际检查；不能用配置文字冒充协商结果。可通过Chrome的chrome://webrtc-internals查看协商与统计（只本机查看，不发送含凭证的完整转储）。共享、主持人会控、DeepSeek不在本阶段。
