## 已实现与复用

- `/history` 默认查询已结束会议，可按状态（含全部、进行中、结束中）、标题或会议号搜索，按游标加载更多。列表、详情都只允许主持人/实际参会者；知道会议号、打开过准备页或仅预留席位不获得历史权限。
- `/history/:id` 展示真实会议、实际参会者、累计参会时长和每段入离时间。时长来自原 attendance_intervals；重连不重复开区间，最终离会关闭，重入另开区间。进行中的时长以本次读取为截止，不伪装为最终时长。聊天复用原有受权分页接口，纯文本显示、支持加载更早记录。
- 每人每场一份手动笔记，其他主持人/实际参会者可读；编辑目标由JWT身份决定，客户端不能指定他人作者。保存使用 version 乐观锁，冲突409保留本地内容，并展示服务器版本供用户比较后选择；没有静默覆盖。已保存内容刷新/服务重启恢复。会议内“会议笔记”弹窗不重建媒体连接。
- 原有聊天未读、发送中/已发送/失败、原clientMessageId重试复用；仅补齐连接同步阶段不重复累计未读。历史消息和本人消息不增加未读。普通回归仍验证丢ACK重试只写一次、105条补拉、离会/重连规则。
- 设备列表沿用 devicechange 自动刷新，会议设置增加手动“刷新会议设备列表”。当前设备 ended 后提示并停止采集；选择关闭状态的输入设备只保存偏好，不调用SDK采集，待本人主动开麦/开摄像头再采用该设备。不擅自选择其他设备并打开。
- 已有认证IP、业务WS聊天限流保留；新增有界、进程内、按登录会话分类的私有API读/写/创建桶。429返回Retry-After；退出登录不受私有写桶阻断。进程重启会重置限流计数，这不是分布式限流。
- 空房/最长时长调度复用第五阶段结束与媒体清理。先持久化 ending、拒绝重入，媒体成功才 ended；失败保留待重试，不假报成功。有效joining预留和45秒reconnecting宽限都不计为空房；空房时间存入原last_empty_at，重启不重置。开始时间用于最长时长，旧的已超时活动会议升级后同样适用。
- SIGTERM停止HTTP接入、通知并关闭WS、停止调度/恢复worker并有界等待；普通服务重启保留恢复凭证、原45秒期限、聊天与参会区间。没有引入第七阶段模型调用或自动纪要。

## 新配置与默认值

新增配置都有默认值，原 `.env` 无需补齐也可启动：

| 配置 | 默认 | 含义 |
|---|---|---|
| MEETING_EMPTY_TIMEOUT_SECONDS | 0 | >0时覆盖原空房分钟设置，0沿用原分钟配置 |
| MEETING_MAX_DURATION_SECONDS | 0 | >0时覆盖原最长时长分钟设置，0沿用原分钟配置 |
| MEETING_SWEEP_SECONDS | 5 | 调度轮询间隔，实际触发有约一个间隔的延迟 |
| API_READS_PER_MINUTE | 600 | 每登录会话私有读请求上限 |
| API_WRITES_PER_MINUTE | 120 | 每登录会话私有写请求上限（不含独立创建桶） |
| MEETING_CREATES_PER_MINUTE | 20 | 每登录会话创建会议上限 |

原 MEETING_EMPTY_TIMEOUT_MINUTES=10、MEETING_MAX_DURATION_MINUTES=240 保持兼容。秒覆盖值0不是关闭调度。秒覆盖最大一年，分钟最多525600；轮询和限流必须为正整数。系统环境变量仍优先于显式加载的 `.env`。无需新增密钥，已有JWT和LiveKit配置保留。
