# Comeet 会议室界面问题记录与修改方案

日期：2026-11-13。供 Codex 实施。当前为第四阶段界面调整，不代表第四阶段音视频已验收通过。

## 1. 本次用户决定与优先级

本说明覆盖原开发文档中“会议室默认深色”和仅宫格的界面约定。新的明确要求为：会议室采用浅色；正常连接信息退出核心界面；视频尽量利用可用空间；用户可选择自己或他人的画面为主画面；为第五阶段屏幕共享预留同样的画面选择机制。

当前只修改界面和必要的本地观看状态，不提前开发第五阶段屏幕采集/发布或主持人会控。已有第四阶段音视频逻辑保留并回归测试。先检查实际代码，再按本说明调整，不重写认证、数据库、业务 WS 或重连协议。

## 2. 问题记录与对应方案

| 编号 | 当前问题/用户意见 | 修改方案 |
|---|---|---|
| UI-01 | “业务已连接”“媒体已连接”等实现用语直接占据核心界面 | 正常时不展示文字条；顶栏提供小型“连接详情”入口，展开查看独立状态。真正故障才显示用户可理解的短提示 |
| UI-02 | 顶部留白过大，媒体区有多层容器和大量内边距，画面实际面积不足 | 顶栏约 56px、底部工具栏约 64–72px，中间占满剩余高度；取消会议页全局侧栏和多余大卡片 |
| UI-03 | 希望摄像头画面更大，不能始终只有并排小卡片 | 提供“聚焦”和“宫格”两种布局。聚焦默认，一个主画面占媒体区主体，其他来源在底部缩略条 |
| UI-04 | 希望自主选择看自己或别人，不由系统随意切换 | 点击缩略图或成员列表“设为主画面”，仅改变本人的观看选择；选择自己也能放大；提供“恢复自动选择” |
| UI-05 | 后续共享内容需要最大化 | 第五阶段把屏幕共享作为独立来源接入主画面，优先展示共享内容，不把共享者摄像头当作共享画面；提供收起侧栏/专注观看 |
| UI-06 | 参会列表位置需要调整 | 右侧可收起面板，成员/聊天两个 tab，默认收起；工具栏显示“成员（人数）”和“聊天（未读）”入口 |
| UI-07 | 不喜欢深色会议室 | 页面、顶栏、工具栏、面板和无视频占位统一浅色；真实视频内容无需人为调亮 |

## 3. 推荐布局与尺寸

采用“紧凑顶栏 + 可伸展媒体区 + 可收起右栏 + 固定布局工具栏”。

- 顶栏：左侧会议标题和会议号/复制入口；右侧布局选择、连接详情、专注观看。标题长则省略并可查看完整文本，不撑高整行。
- 媒体区：桌面默认聚焦布局，占据主体宽度；右栏关闭时自动用满宽度，不保留一块空白。外侧 padding 12–16px，内部 gap 8–12px，避免多层卡片套卡片。
- 主画面：优先使用剩余高度，姓名、本人/主持人及麦克风状态用紧凑角标，不在画面下方另开大段文字区。
- 缩略条：位于主画面底部，高度约 96–120px，横向滚动；主画面当前来源不再重复渲染一张活动视频，只提供紧凑已选标识或排除该来源。只有一个来源时隐藏整条。
- 右栏：宽约 300–340px，成员/聊天共用一个位置；列表内部滚动，聊天输入区始终可见。默认关闭，不从用户使用中自动弹出抢空间。
- 底部：麦克风、摄像头、成员、聊天、设备设置、离开会议；共享入口等到第五阶段真实实现再开放。设备选择放在按钮箭头弹层或设置弹窗，不长期放在右栏顶部。
- 离会只保留一个明显入口，避免顶部“离开返回工作台”和底部离会重复。既有主持人离开/结束区别保持不变。
- “专注观看”收起右栏与缩略条，顶栏和必要工具保留；“退出专注”清楚可见。这不同于浏览器全屏，可选增加全屏按钮但不依赖全屏 API 才能用。

容器建议使用 CSS Grid/flex：根容器 min-height:0、height:100dvh，行高 auto/minmax(0,1fr)/auto；主体列 minmax(0,1fr) + 可选右栏。子区 min-width:0/min-height:0，避免默认最小尺寸引起横向溢出。桌面会议页不使用整页纵向滚动撑出工具栏；列表单独滚动。极窄/极矮窗口可合理滚动，核心按钮不能被裁掉。

宫格仍保留：1 人单画面，2 人并排充分占用，3–4 人自适应两列，5–6 人按可用宽高选择 2 或 3 列，不固定每格小高度。媒体容器适配画面比例，不用空白 padding 把视频挤到中央。

## 4. 主画面来源及选择规则

### 4.1 区分参与者和画面来源

参与者用稳定 user/session identity 标识，来源包含 participantIdentity + source（camera/screenShare），不要用数组下标或短暂 trackSid 保存选择。第五阶段同一人可以同时有摄像头和屏幕共享，必须可以分别选“某某的摄像头”“某某的共享”。成员列表始终每人一行，不因两条视频变成两名成员。

每个用户自己的主画面选择只保存在本地会话/UI 状态中，不广播给其他人、不影响主持人权限、不修改媒体发布设置。切换画面只改变观看布局，禁止重连房间、重新采集或重新发布轨道。小项目保留现有订阅策略即可，不为本次 UI 修改引入复杂手动订阅编排。

### 4.2 自动与手动

- 默认聚焦布局，初始为自动选择：有共享时选共享；否则优先一个已开摄像头的远端成员；其次自己的摄像头；都未开时选一个成员占位。
- 自动选择一旦取得有效来源就尽量稳定，新人加入不来回跳动；当前来源失效才按优先级回退。共享首次出现时，只有处于自动模式才优先切过去。
- 点击任意成员缩略图/“设为主画面”进入手动模式，显示已选边框及“主画面”标记。选择自己的本地预览必须支持。
- 手动选择优先，不因谁说话、有人入会或开始共享而强制更换。以后有人共享可给轻量“某某正在共享 · 点击查看”提示，不自动抢走已固定的画面。
- 当前已选摄像头关闭：保留该参与者的主画面位置，显示浅色头像及“摄像头已关闭”，可以自行换人；不能展示冻结的最后一帧。
- 所选共享停止或所选成员正式离会：来源失效，自动回退并清除失效选择，给短提示；短暂重连保留所选人并显示重连占位，避免抖动。
- “恢复自动选择”清除手动固定，立即根据现有可用来源重新计算。
- 从聚焦切宫格不清除有效手动选择，返回聚焦仍能恢复；本场退出后清空选择，不影响下一场。
- 在宫格点击“放大/设为主画面”时进入聚焦并选中对应来源。

不开发自动演讲者视图；说话状态可小型高亮，但不能偷偷改变主画面。

### 4.3 视频呈现

主画面摄像头默认 contain，保持完整构图，不拉伸、不为填满牺牲人脸和内容；剩余空间使用很浅中性色，不是大片深色装饰背景。缩略图可 cover。第五阶段共享必须 contain，字和表格不裁切、不镜像。

本地摄像头可镜像且静音播放，远端摄像头和共享不镜像。音频统一挂载一次，不能因主画面和缩略图切换而声音重复或消失。轨道 attach/detach 与组件 key 正确，复用 SDK/已有轨道渲染，避免重复消费画面和泄漏事件。

## 5. 成员和聊天的具体位置

右侧面板默认关闭，在工具栏点击打开。已打开成员时再次点击成员可关闭，点聊天则切到聊天页；反之同理。关闭不清空聊天、不重新请求整场数据，也不影响未读统计。

成员行：头像、姓名、本人/主持人小标记、实际麦克风/摄像头图标、可选重连中；菜单提供“设为主画面”。当前主画面来源是共享时，行菜单分别提供看摄像头/看共享（等第五阶段有真实来源再显示）。不能只用颜色表达状态。

聊天消息减少大卡片和过高 padding，紧凑展示发送者、正文和弱化时间。正常已发送标记弱化，不必每条突出“已发送”；失败/重试必须清楚。输入区固定于右栏底部，历史单独滚动。成员人数与未读来自现有真实状态，不生成假数据。

小屏（例如宽度小于约 768px）成员/聊天改覆盖式抽屉，不挤成极窄媒体区；有清楚关闭入口、焦点管理。缩略条允许横向滚动，工具栏保留核心按钮、次要项收进“更多”。

## 6. 连接与故障提示

用户不需要常驻阅读“业务/媒体”实现术语，但底层必须继续分别管理状态。

| 情况 | 核心界面呈现 | 详情入口 |
|---|---|---|
| 均正常 | 不显示“已连接”文字条；只保留可点击的小型连接图标 | “聊天与成员连接：正常；音视频连接：正常” |
| 初次连接中 | 媒体区紧凑占位“正在连接会议…”；不制造大页头 | 各通道真实状态 |
| 业务断开 | 短条“聊天与成员同步暂时中断，正在重连” | 可查看技术状态 |
| 媒体断开 | “音视频连接中断，正在重连；聊天仍可用”（仅聊天确实可用时） | SDK 实际连接状态 |
| 权限/设备问题 | 对应设备旁提示和重试/设置入口 | 清楚说明被拒绝或缺设备 |
| 自动播放被阻止 | 保留可点击的“播放会议声音” | 不隐藏到诊断页 |
| 不可恢复 | 明确错误及重新加入/返回入口 | 不无限显示重连 |

恢复后自动收起临时异常条，避免重复 toast。技术诊断可放在连接详情或现有设置页，不增加工作台诊断面板。图标用 button，有 aria-label、tooltip，触屏点击也能查看，不只依赖 hover 或颜色。

本次不能为了隐藏正常状态而把所有错误都隐藏；聊天失败、设备权限和音频播放受阻仍要可见可操作。

## 7. 浅色主题

可使用以下基准并根据现有设计微调：页面 #F5F7FB、面板/顶栏/工具栏 #FFFFFF、主文字 #1F2937、次文字 #64748B、边框 #E2E8F0、主色 #4F5FE8。保持文本和交互状态有足够对比，禁用态仍可辨认。异常用适度红/橙，不用大片警报色。

头像/关摄像头占位采用浅蓝灰，删除原深色大背景；视频本身或共享源是黑色属于真实内容，不能通过滤镜改亮。无须本次开发完整深浅切换设置，先统一浅色并移除会议室强制深色覆盖。

## 8. 分批实施，避免跨阶段

### 当前第四阶段内完成

1. 浅色会议室、紧凑顶栏/工具栏、清理冗余留白。
2. 默认聚焦/可切宫格、手动选择自己/他人、自动回退、专注观看。
3. 右侧成员/聊天可收起、设备设置迁移。
4. 正常连接信息收纳，故障仍可见。
5. 音视频及已验收的聊天/重连/离会回归。

屏幕共享尚未实现时不显示伪造共享源、不启用共享按钮；仅把来源模型和布局留好扩展位置。用户尚未确认第四阶段真实音视频验收通过，不得擅自标记通过或自动进入第五阶段。

### 第五阶段再接入

真实共享轨道、共享来源选择、自动模式共享优先、共享停止回退，与上述主画面逻辑整合。共享者摄像头与共享内容分别标识，不把两者混为一张卡片。

## 9. 验收清单

本次界面改完后提供实际启动命令和以下人工验收方法，不只写“按 README”。

1. 在 1440×900 和 1366×768 等桌面窗口，页面浅色，顶栏紧凑；无正常业务/媒体状态长条；工具栏无需滚到页底才能看到。
2. 两账号开摄像头，聚焦主画面明显大于缩略图；右栏收起后媒体立即扩展，无空白占位列。
3. 选择自己，自己的画面最大；选择他人，切换准确，只影响当前浏览器。宫格到聚焦切换正常，不重连或重复申请设备。
4. 开关所选摄像头、成员短暂重连/正式离会后，按规则占位或回退，不冻结最后一帧、不显示错人。
5. 成员/聊天打开、切换、收起正常；聊天输入区可见、未读保留、列表不撑坏整页；缩略条可滚动。
6. 两人通话和双向聊天正常；切换画面多次不出现双重声音、无声、黑屏或轨道泄漏；离会后设备释放。
7. 模拟业务或媒体异常，短提示准确、可重试；恢复后收起。连接详情可打开，技术状态真实。
8. 390px 窄屏主要按钮和抽屉可用，无不可控横向溢出。

第五阶段额外验收：共享内容最大且完整、可选自己/别人摄像头或共享、多共享源选择、手动选择不被抢占、停止共享自动回退。

自动检查只针对有风险的选择/回退逻辑和已有业务回归，补充必要组件测试、类型检查和构建；提供实际结果，不为简单颜色调整编写大量脆弱截图测试。实机音视频和屏幕共享以真实操作为准。
