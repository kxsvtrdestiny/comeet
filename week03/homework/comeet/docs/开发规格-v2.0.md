# Comeet 开发文档：分阶段开发与人工验收版

版本：2.0｜更新日期：2026-11-09｜技术方案：React + TypeScript + Go + SQLite + LiveKit + DeepSeek。

本文是交给 Codex 的开发规格，不代表功能已实现。本版本完整替代上一版：保留全部基础要求，选取主要实用进阶功能，挑战功能以 DeepSeek 纪要为重点。刷新令牌轮换、持久化媒体任务队列、分布式状态、严格共享抢占、复杂监控不属于本次必做范围。

## 1. 给 Codex 的执行规则

### 1.1 开发目录与工作方式

所有项目文件放在 `week03/homework/comeet`。先读取仓库 AGENTS.md 和现有代码，确认实际工具及版本，不修改其他作业。保留已有正确实现，不为套用模板而重写整个仓库。

**严格采用“Codex 完成一阶段 → 用户本机运行并验收 → 用户明确确认后再开发下一阶段”。**

- 收到本文件后，只开发第 1 阶段，不提前开发后续业务。
- 每阶段不止输出计划，必须实际完成代码、运行可执行检查、更新文档，最后提供用户可照做的 Windows 运行和验收步骤。
- 阶段完成即停止。只有用户明确说“第 N 阶段验收通过，继续下一阶段”或同等意思，才推进。用户上传截图、报告报错或要求修改时，仍处于当前阶段。
- 用户发现问题，先在当前阶段修复并给出复测步骤，不叠加后续功能。用户说“继续修复”不等于批准进入下一阶段。
- 每阶段更新 `docs/阶段验收.md`：代码完成状态、自动检查结果、人工待测项目、用户反馈和验收结论。不能替用户声明实机验收通过。
- 普通可逆代码修改自主完成。不要未经要求 push、购买服务、公开部署或提交用户的密钥。
- 若用户允许 Codex commit，提交说明使用 `feat:`、`fix:`、`docs:`；push 需要另有明确指示。

### 1.2 真实性与范围

全部基础功能优先。严禁用静态演示数据冒充 SQLite 数据、用本地聊天冒充实时通信、用假视频冒充远端视频、用固定文本冒充 DeepSeek。测试 mock 可以使用，但不能进入正常运行链路。

缺少网络、媒体配置、模型 Key 或域名时，继续完成不依赖它们的工作，明确“代码已完成、真实联调待验证”。不能把 mock 测试通过写成真实服务通过，也不能用“浏览器打开了”代替音视频验收。

目标是单实例课程项目：桌面 Chrome/Edge、2–6 人小型会议，至少两名不同账号、两个独立浏览器环境真实互通。六人上限是产品配置，不是经过压测的性能保证。前后端和媒体服务分离；允许使用第三方媒体服务，但必须自行实现 Go 业务服务和 SQLite 持久化。

### 2.3 挑战功能

**本次重点实现：基于聊天和手动笔记的 DeepSeek AI 纪要。** 支持生成、保存、失败后重试、查看、Markdown 导出。始终标注“不含语音转写”。不做实时字幕或语音输入。

完成基础生产构建、环境变量说明和 HTTPS 部署方案；无需用户现在购买服务器或域名。Docker/Caddy 实际部署、Prometheus、自动演讲者视图作为全部主要功能验收通过后的可选任务，不能未经用户同意自动开展。

不做：录制回放、实时字幕、虚拟背景、通用 AI 助手、Redis、多实例、分布式任务队列、刷新令牌轮换、复杂共享锁和监控平台。

## 3. 技术方案与依赖

| 部分 | 采用方案 | 职责 |
|---|---|---|
| Web | React + TypeScript + Vite、React Router | 页面与交互 |
| 状态 | Zustand + 封装 fetch | 会话、房间业务状态、UI；避免重复缓存 |
| 样式 | CSS 变量 + 普通 CSS、Lucide 图标 | 简洁统一的设计体系 |
| Go | net/http + chi、coder/websocket | REST、业务 WS、鉴权和状态 |
| 数据库 | database/sql + modernc.org/sqlite | 纯 Go SQLite，减少 Windows CGO 问题 |
| 身份 | golang-jwt/jwt/v5 + bcrypt | 业务 JWT、密码哈希 |
| 媒体 | livekit-client、Go 官方 server-sdk-go/v2 | WebRTC 与 SFU、屏幕共享、媒体管理 |
| AI | Go net/http 调用 DeepSeek Chat Completions | 不增加 Node AI 服务 |
| 测试 | Go testing/httptest、Vitest/RTL、必要的 Playwright | 业务与关键用户路径 |

允许使用 LiveKit React 基础轨道组件，但页面自己设计，不照搬整套会议 UI。不要同时安装多套状态库、UI 组件库或请求库。若已有仓库技术选择正确可复用，说明必要的小差异即可。

实施时核对官方 API 和兼容版本；在 package-lock.json、go.mod/go.sum 中锁定，容器若使用也锁定具体版本。README 记录真正使用的 Node、Go、浏览器及主要 SDK 版本，不能写未经验证的“最新版”。

### 3.1 业务信令与媒体分离

- 浏览器 → Go REST：账号、会议、历史、会控、媒体令牌、AI 纪要。
- 浏览器 ↔ Go WebSocket：加入/离开、成员快照、聊天、会控结果、会议结束。
- 浏览器 ↔ LiveKit：SDK 内部媒体信令及 WebRTC 音视频。
- Go → LiveKit 管理 API：获取成员、静音、移出、删除房间。

Go 必须有自己的 WebSocket，不能只用 LiveKit 数据通道替代。SDP/ICE 协商交给 SDK，Go 业务 WS 不重复转发 SDP/ICE。

业务连接和媒体连接分别维护状态。媒体失败时聊天仍可使用；业务连接断开时聊天和会控显示不可用，不把“还看得到视频”当作业务在线。

### 3.2 LiveKit 运行方案

优先用 LiveKit Cloud，用户自行配置服务地址、Key、Secret；费用和额度由服务账户决定，不在代码里承诺免费额度。准备一份可选本机开发说明，若提供自托管示例，密钥只能用于本地开发。

Cloud 联调不要求 Go 公网 Webhook；首版使用 SDK 轨道事件渲染和 Go 管理 API 按需查询/短周期对账。Webhook 验签可选扩展，不能成为本机开发的前置条件。

只要求用户到第 4 阶段时配置 LiveKit，不要第 1 阶段就因为没有媒体 Key 无法启动。到第 7 阶段再配置 DeepSeek。所有缺失配置在 UI 明确说明，不能服务启动后才神秘失败。

## 4. 视觉与页面

界面参考用户截图的流程和信息，不复制其 Logo、布局和装饰。页面使用简体中文，清楚、简洁、留白适中。主色蓝/靛蓝，浅灰白背景、深灰正文，圆角 12px 左右，少量边框和阴影，不做大面积渐变光晕和花哨动画。

统一 8px 间距体系，正文 14–16px，系统中文字体，主次按钮明显。桌面工作台使用侧栏与内容区；会议室默认深色。全站可先固定主题，不强制额外实现主题切换。

至少检查 1440、1024、768、390px。小屏侧栏折叠，聊天/成员抽屉展示，工具栏不遮挡主要操作。不要求移动端音视频达到桌面完全一致，但说明实际测试浏览器范围。

- 摄像头关闭显示姓名/头像，不能显示假画面。

- 多人共享时提供共享源选择；当前共享停止后选择其他可用源，没有共享则返回宫格。

## 5. 账号与安全：采用简单可靠的方案

### 5.1 JWT 与登录会话

不做刷新令牌。登录生成业务 JWT，有效期默认 8 小时，可配置；payload 含 sub、sid、iss、aud、iat、exp。服务端每次校验签名算法、时间、发行者、受众及会话是否撤销。auth_sessions 存 sid、user_id、expires_at、revoked_at，不存明文 JWT。

Web token 存 sessionStorage，刷新页面可保持，关闭标签后不保证继续登录。不使用 localStorage 长期保存，不做“记住密码”。该选择简化实现但不能防止 XSS，所以聊天/笔记纯文本渲染、禁止未经净化的 HTML。登录失败统一提示，避免泄露是否存在账号。

登出撤销当前 sid、清理当前标签的身份和媒体、服务端关闭该 sid 对应 WS 和媒体会话。过期返回 401，前端清理并转登录，保留会议返回地址；重新登录后允许重进活动会议。WS 也必须在 JWT 到期时失效，不能只握手验一次就永不过期。

用户名 3–32 位字母数字下划线，大小写规范化并设唯一约束；显示名称 1–32 字符。密码至少 8 字符且 UTF-8 不超过 bcrypt 的 72 字节上限；哈希存储，不记录明文。标题最多 80 字符。SQL 参数化，所有 HTTP body 限制大小。

### 5.2 WebSocket 鉴权与安全

浏览器 WS 不方便带 Authorization 头，因此用已登录 REST 申请单次 ticket（30 秒），URL 仅含该短票据。后端原子消费，检查 Origin 白名单、绑定用户/sid/会议/参会会话；长期 JWT 不放 URL。日志隐藏 ticket、token、密钥。

所有带会议或会话 ID 的接口做对象级权限校验，不是“登录了就能看所有会议”。客户端不能指定主持人身份、聊天发送者、服务端时间。只有 Go 调用媒体管理 API，浏览器媒体 token 不能含 roomAdmin。

基础限流按登录、会议号查询、聊天、纪要生成分别实现，429 有友好提示。只信任明确配置的代理 IP，不盲信 X-Forwarded-For。

## 6. 会议与成员规则

### 6.1 会议生命周期

创建会议即 active；started_at 为创建时间；准备页不算实际参会。结束流程 active → ending → ended，结束请求幂等，ending 期间拒绝加入和新媒体 token。主持人固定为创建者。

**主持人个人离开不结束会议，也不自动转移主持权。** 主持人可重新加入，或在自己的活动会议详情中结束。确认框分开“离开会议”和“结束所有人的会议”。结束后历史可读，不可再入会。

会议号 9 位数字，展示 123-456-789，支持去除空格/连字符后校验；crypto/rand 生成、数据库 UNIQUE 冲突重试。内部 UUID 与会议号分开，LiveKit room name 用内部不透明 ID。

默认最多 6 名在线/重连/预留成员。打开准备页不占名额，点击入会时原子预留 60 秒；超时释放。后端事务与唯一约束防止并发超员，不靠前端人数判断。

第 6 阶段加基础调度：空房 10 分钟、最长 4 小时自动结束，参数可配；重连宽限期不算空房。用户手动离开后当前人数正确，不能一直留下幽灵成员。

### 6.2 入会与重复入会

Go join 校验活动状态、容量、封禁、权限，创建 participant_session。返回 sessionId 和随机恢复凭证；恢复凭证只存哈希，浏览器 sessionStorage 保存原值。相同客户端请求 ID 重试不新建会话。

业务 WS room.join 成功时才写参会记录；仅打开详情/准备页不产生参会历史。业务入会后可先聊天，再连接媒体；媒体失败不撤销已经有效的文字参会。

同用户同会议只允许一个有效参会会话。新标签重新 join 返回 ALREADY_JOINED，不自动顶掉原连接。恢复需要同一登录身份、原 sessionId 和恢复凭证。浏览器复制标签可能复制 sessionStorage：已有健康 WS 时拒绝重复恢复；只有服务端已认定原连接断开后才允许接管，不能单凭凭证强行替换健康连接。

### 6.3 断线与恢复

业务意外断开标记 reconnecting，宽限期 45 秒，保留席位。重连延迟 1/2/4/8 秒，最大 10 秒并加抖动；成功后恢复快照、分页补消息。超过宽限期结束原会话，提供“重新加入”；不无限重连。

连接表用 generation 或等效标识，旧 WS 的关闭回调不能删除新 WS。SDK 媒体重连交给 SDK，不因每次业务 WS 重连就重复 room.connect。媒体失败有单独重试入口。会议 ended、被移出或认证失效停止重连。

主动离会即时清理本地资源，并幂等通知后端。页面崩溃依赖心跳和宽限期兜底，不能仅靠 beforeunload。Go 服务重启后旧在线记录先进入恢复状态，允许原凭证恢复；宽限超时关闭，持久化会议和聊天不能丢失。内存 WS ticket 可失效，客户端重取。

业务在线状态由 Go 会话决定；实际麦克风/摄像头状态由 LiveKit 轨道事件决定。媒体管理密钥和 SDK 查询用于会控及校对，不能把客户端自报 role 当作真实权限。

## 7. 数据模型

SQLite 单实例运行；migration 编号并记录版本；启用 foreign_keys、WAL、busy_timeout。可使用单连接/序列化写入简化并发，所有事务要短，不持有数据库事务调用外部网络。时间统一 UTC Unix 毫秒，前端格式化。

| 表 | 主要字段与约束 |
|---|---|
| users | id，username，normalized_username UNIQUE，display_name，password_hash，created_at |
| auth_sessions | id，user_id FK，expires_at，revoked_at，created_at |
| meetings | id，meeting_no UNIQUE，title，host_user_id，livekit_room_name UNIQUE，status，started_at，ended_at，last_empty_at |
| meeting_members | id，meeting_id，user_id，display_name_snapshot，first_joined_at，last_left_at；UNIQUE(meeting_id,user_id) |
| participant_sessions | id，meeting_id，user_id，auth_session_id，resume_hash，state，generation，reserved_until，joined_at，last_seen_at，disconnected_at，left_at |
| attendance_intervals | id，participant_session_id，joined_at，left_at；用于重复进出和时长，重连不重复开区间 |
| meeting_bans | meeting_id，user_id，created_by，created_at；联合唯一 |
| chat_messages | id 自增游标，meeting_id，sender_user_id，sender_name_snapshot，client_message_id，content，created_at；UNIQUE(meeting_id,sender_user_id,client_message_id) |
| meeting_notes | id，meeting_id，author_id，content，version，updated_at；每人每场一份笔记可直接联合唯一 |
| meeting_summaries | id，meeting_id，requested_by，status，source_hash，source_snapshot，model，result_json，error_code，created_at，updated_at |

joining/online/reconnecting 属于有效会话，数据库部分唯一索引保证同用户同场最多一个。interval 在真正业务入会时创建，最终离会/结束时只关闭一次；短暂重连不累计两遍。姓名用参会和消息快照，改名后历史不混乱。

历史权限：只看自己创建或实际参加的会议。没有参加过、仅知道会议 UUID 或会议号不能查询聊天、笔记和纪要。主持人可以查看自己创建的会议详情。

不建刷新令牌表、共享租约表、持久化媒体操作队列、复杂审计仓库。必要少量字段可由实现补充，但不能随意改变本文件规则。

## 9. WebSocket 与聊天一致性

客户端帧示例：

```json
{"v":1,"type":"chat.send","requestId":"uuid","payload":{"clientMessageId":"uuid","content":"大家好"}}
```

服务端帧示例：

```json
{"v":1,"type":"chat.created","eventId":"uuid","meetingId":"uuid","payload":{"id":101,"clientMessageId":"uuid","senderId":"uuid","senderName":"小明","content":"大家好","createdAt":1794182400000}}
```

| 方向 | 类型 |
|---|---|
| C→S | room.join、room.leave、chat.send、ping |
| S→C | room.snapshot、member.joined、member.updated、member.left、chat.created、chat.ack、meeting.ending、meeting.ended、member.removed、error、pong |

room.join 只能进入票据绑定会议。room.snapshot 包含当前成员、会议状态、最新消息游标；成员变化时可以广播完整小房间成员快照，避免引入复杂版本增量协议。每次新连接都以完整快照替换旧成员状态，不跨旧连接应用迟到事件。

聊天规则：

1. 纯文本，trim 后不能为空；最多 2000 Unicode 码点、8KiB；正常 WS frame 上限 16KiB。
2. 先成功写 SQLite，再广播并 ACK。失败返回 requestId 对应错误，前端显示失败。
3. clientMessageId 由前端生成；重试沿用原 ID，数据库唯一约束，重复请求返回原消息，不能再插一条。
4. 前端服务端 ID 去重，clientMessageId 匹配发送中占位消息；ACK 与广播顺序任意都不能重复。
5. 先注册实时订阅并缓冲，再返回快照高水位；客户端从最后消息 ID 分页补拉至高水位，再合并缓冲。不能只取最后 50 条就宣称恢复完整。
6. 补拉返回 nextCursor/hasMore；消息按服务端 id 排序，不靠客户端时钟。
7. 未读仅计算未查看的新远端消息，历史加载和自己的消息不增加。
8. 每个 WS 一个读循环、一个写循环、有界队列；慢客户端断开并恢复，不阻塞全房；异常 JSON/未知类型不让 Go 崩溃。

服务端心跳建议 10 秒，30 秒无响应关闭；随后开始 45 秒恢复宽限。客户端手动恢复遇到服务端暂未判定旧连接关闭时，按提示短暂重试，不强抢健康连接。后台标签计时可能节流，要通过真实浏览器验证。

## 10. 媒体、设备与会控细节

### 10.1 采集、预览和播放

麦克风与摄像头独立申请；摄像头失败不丢弃可用麦克风。关闭设备时不偷偷重新打开；无设备/拒绝权限仍可仅聊天。准备页不发布轨道，入会可复用或停止后重建，禁止同时采集两套。

捕获 NotAllowedError、NotFoundError、NotReadableError、OverconstrainedError，映射为可理解文字和“重试/更换设备/仅聊天”。授权前设备标签可能为空，用友好编号。

麦克风电平用 AnalyserNode；离开页面关闭 AudioContext、节点和动画循环。扬声器试听仅在用户点击后播放短音调，有停止按钮。输出设备选择仅在 setSinkId 等实际支持时提供，否则用系统默认，不能显示假切换成功。

devicechange 刷新列表，并提供手动刷新；当前设备失效提示“设备已断开，请选择其他设备”，不强行开启新设备。用户切换通过 SDK 实现，保持静音/摄像头开关选择。

摄像头默认约 720p/30fps、VP8、Simulcast；使用 adaptiveStream/dynacast，参数按当前锁定 SDK 官方说明核对。用 SDK attach/detach 或正确基础组件订阅，清理事件监听；React StrictMode 不能双连接。

### 10.2 屏幕共享

getDisplayMedia 必须由用户点击直接触发，不能在异步网络等待后丢失用户激活。SDK 可用时使用其屏幕共享方法，但必须核对用户手势要求。

取消浏览器选择是正常取消。监听轨道 ended，使系统“停止共享”和页面停止按钮走同一清理路径。允许多个成员共享，不做全局锁；共享源选择默认当前首个可用源，选择变化不得重复播放声音。屏幕使用 contain，不镜像。

共享声音仅浏览器/系统实际采集到音轨时发布，不承诺每个平台支持。没有音轨不显示“正在共享系统声音”。

### 10.3 主持人操作与失败

静音：Go 校验主持人，从服务端查询目标麦克风 TrackSid，调用 MutePublishedTrack。没有发布麦克风时提示“该成员当前未开麦”。静音成功后提示对方“主持人已将你静音，你可以自行开麦”；不实现持续发布权限封锁，不远程开麦。

移出：SQLite 记录本场封禁、使业务会话不可恢复，调用 RemoveParticipant，关闭业务 WS。不能仅隐藏姓名。此后 join、resume、media-token 都拒绝。媒体失败时显示“移出未完全完成，可重试”，封禁仍保留，再次操作幂等。

结束：先持久化 ending 拒绝新加入，通知客户端离开，调用删除媒体房间并按需要移出已知媒体身份，成功后 ended 并关闭参会区间。依赖失败时保留 ending 和错误，可由主持人点击重试；启动时重试 ending 会议。不引入通用持久化任务队列，但不能把失败操作报告为成功。

Cloud 移出调用核对并使用当前 SDK 支持的明确撤销截止时间，防止默认时钟缓冲让刚签发的旧令牌仍可重连。media token TTL 5 分钟，无 roomAdmin；业务封禁始终拒绝新 token。短 TTL 不会切断已连接用户，自托管也不保证撤销旧 token，应如实记录边界；不能把仅关 WS 当作安全移出。真实验收需要尝试旧 token 重连，选定 Cloud 模式完成严格测试。每次入会 identity 绑定服务端会话，不允许前端指定其他用户身份。

### 10.4 清理

所有离会入口复用幂等 dispose：停止 mic/camera/screen tracks，断开 LiveKit，detach 媒体/清理 srcObject，关闭 AudioContext，取消动画、重连和检测计时器，移除监听，关闭业务 WS，清理当前会议敏感数据。页面跳转、退出登录、结束会议、移出都覆盖；检查浏览器设备占用指示是否停止。

## 11. DeepSeek 会议纪要

### 11.1 数据和权限

仅会议 ended 后，主持人手动点击“生成 AI 纪要”。第一次操作确认将本场聊天与手动笔记发送到 DeepSeek；不发送密码、token、其他场会议数据或不必要个人信息。其他实际参会成员可查看、导出成功结果。

页面固定标注：**“由 DeepSeek 基于聊天与手动笔记生成，不含语音转写，请核对内容。”** 无有效聊天/笔记时提示记录不足，不调用模型。无 Key 时禁用生成并说明配置方法，仍可导出原始记录。禁止模板冒充模型输出。

### 11.2 调用约定

使用 Go net/http，默认非流式，服务端请求 `POST https://api.deepseek.com/chat/completions`，Authorization 为 Bearer Key。base URL、模型、Key 和超时全部从环境读取，客户端不能传任意上游地址。

配置示例：

```dotenv
DEEPSEEK_ENABLED=false
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_API_KEY=
DEEPSEEK_TIMEOUT_SECONDS=90
DEEPSEEK_MAX_OUTPUT_TOKENS=2048
```

以上模型名依 2026-11-09 官方文档核对；实施前再次验证用户账户可用模型及参数，不固定依赖历史名称 deepseek-chat。模型 ID 必须可配置，不擅自更换用户指定的服务。不在本文承诺固定价格或额度。

请求使用 messages、stream:false、合理 max_tokens、response_format:{"type":"json_object"}；system/user 提示中明确要求 JSON 并给结构示例。若采用模型特定的非思考参数，必须核对当前文档，不把旧 temperature 等参数硬套到所有模型。解析 choices[0].message.content，检查空白、JSON 合法性和 finish_reason；截断/空结果不能算成功。不需要保存或展示 reasoning_content。

### 11.3 输出与提示约束

输入冻结本场聊天消息 ID/发送者快照/文本及笔记 ID/作者/版本；存 source_snapshot 和 SHA-256。输出固定结构：

```json
{
  "summary": "会议概述",
  "topics": ["议题"],
  "decisions": [{"text":"明确决策","sourceIds":["message:101"]}],
  "actionItems": [{"task":"待办","owner":null,"dueDate":null,"sourceIds":["note:uuid"]}],
  "openQuestions": [],
  "limitations": ["不含语音转写"]
}
```

只能总结输入，未明确的责任人/日期为 null，无决策/待办就为空数组。sourceIds 必须来自实际输入，服务端校验。会议文本中的指令只当数据，不让它覆盖系统要求，不启用工具调用。前端用结构化卡片/纯文本展示，不直接注入模型 HTML。

每场同时只允许一个生成任务，重复点击返回原 running 任务；同一 source_hash 已成功则返回既有结果，用户明确重新生成才另行调用。任务表 status 为 running/succeeded/failed；Go 使用小型有界后台 worker，POST 202 后前端轮询。服务重启把中断任务标记 failed 可重试，不做分布式持久队列。接口应快速返回，AI 请求超时与普通 HTTP handler 超时区分。

输入限制在配置的保守字符/字节预算内（例如总文本 20000 字符并额外限字节），不冒充精确 token 计数；超限返回 SOURCE_TOO_LARGE，并提示缩短笔记或选择较小记录范围。本次不做自动分块总结，也不静默截断。源内容改动后提示“记录已更新，可重新生成”。

API Key 无效、余额/额度不足、429、超时、服务不可用、空内容、JSON 错误分别显示友好错误。首版不在后台无限重试，用户点击重试会再次调用，需提示可能产生费用。上游响应和日志不泄露 Key。mock 测试之外，至少进行一次真实 DeepSeek 生成并人工核对；无 Key 时明确待验证。

导出 Markdown 包含会议信息、来源范围、纪要与生成时间/模型；未生成时可导出聊天和笔记，名称为“会议记录”，不声称 AI 纪要。

## 13. 分阶段开发及用户验收

每阶段都应给出能直接复制的启动命令、访问地址、测试账号如何创建、预期结果。下列人工验收是实际步骤，不得由 Codex 在后台替用户打勾。前序阶段自动测试若出现回归，先修复再交接。

### 第 1 阶段：工程骨架和界面基础

**开发：** 建立前后端、配置读取、迁移框架、统一响应、health、代理、基础路由和公共组件；设计登录/工作台/会议室骨架。建立 README、DEVELOPMENT、方案初稿和阶段验收记录。不实现真实注册/会议业务，不展示假记录。未完成按钮禁用且标明后续阶段。

**Codex 检查：** 前端类型检查/构建，Go 编译或 test，前端能真正请求 health，准备页路由不崩溃。此阶段不要求 LiveKit/DeepSeek 配置。

**用户运行验收：**

1. 按 README 分别启动 Go 和 Web，浏览器进入主页。
2. 检查登录、工作台、会议室骨架的布局是否简洁美观。
3. health 显示数据库初始化正常，不因没有媒体 Key 启动失败。
4. 缩窄浏览器，主要区域不明显溢出；刷新路由不报错。

**停点：** 用户确认界面方向及启动通过，才进入第 2 阶段。

### 第 2 阶段：账号和会议 REST

**开发：** 注册/登录/JWT/sid 撤销、退出、工作台真实数据、创建会议、会议号 resolve、受限准备信息、join 预留骨架、历史权限。访问受保护页面正确跳转。没有 WS 前明确“正式入会将在下一阶段接通”。

**Codex 检查：** 临时数据库集成测试：用户名重复、错误密码、过期/伪造 token、退出撤销、会议创建幂等、查询不存在号、跨用户详情权限、容量和唯一约束。

**用户运行验收：**

1. 注册账号 A，登录；错误密码有明确提示。
2. 创建会议，拿到 9 位会议号；工作台能显示真实会议。
3. 用账号 B 在另一个浏览器/隐私窗口登录，输入会议号进入准备信息。
4. 错误会议号提示清楚；刷新仍可用；退出后受保护页不可访问。

**停点：** 账号和会议 API 验收通过再继续。

### 第 3 阶段：成员、聊天、离会和业务重连

**开发：** ticket、WS 协议、正式入会、参会记录、成员快照、主持人/本人标记、聊天落库/分页/原 ID 重试、离会、重复入会保护、心跳及自动重连。先完成可用的文字会议。

**Codex 检查：** 两个真实 WebSocket 客户端互通；持久化后广播；重复消息只有一条；聊天补拉超过 100 条；旧连接关闭不误删新成员；鉴权过期；重启后恢复；慢连接有界。

**用户运行验收：**

1. A/B 两个账号加入同一会议，两边人数/标记正确。
2. 双向聊天实时同步，刷新恢复消息，历史没有重复。
3. B 离开后 A 成员列表减少；同账号第二标签不踢原连接。
4. 短暂断网再恢复，看到重连提示且消息补齐；无法模拟时记录待测。
5. 重启 Go 后会议/消息仍存在，连接恢复或明确提示重新加入。

**停点：** 基础文字会议通过后再接音视频。

### 第 4 阶段：设备准备和真实多人音视频

**开发：** 配置 LiveKit、Go 发媒体 token、采集/预览、麦克风/摄像头开关、远端发布订阅、宫格、Simulcast SDK 设置、麦克风电平/试听、声音自动播放兜底、离会清理。

**Codex 检查：** token 只允许当前会议和会话，无 admin；权限错误映射；StrictMode 无重复连接；媒体状态独立。可自动测用测试轨道验证真实服务订阅，无法联调则明确阻塞。

**用户运行验收：**

1. 按说明配置 LiveKit，仅用户自己在 .env 填秘密。
2. A/B 进入准备页，预览与开关正确；电平和试听可用。
3. 两端进入，能看见/听见对方，关摄像头/麦克风实际生效。
4. 拒绝摄像头权限仍可使用其他能力和聊天。
5. 离会后设备占用释放。单机听感测试使用耳机，避免扬声器啸叫影响判断。

**停点：** 真实音视频是必须人工确认的门槛，不能只凭按钮测试进入下一阶段。

### 第 5 阶段：共享、会控和布局

**开发：** 共享启动/停止/ended、共享主画面与多源选择，主持人静音/移出/结束，后端权限、封禁、ending 重试。不做持续禁言和共享抢占锁。

**Codex 检查：** 普通成员 API 被拒绝，媒体 API 失败不虚报成功，移出后拒绝 join/resume/token；Cloud 旧 token 重入测试。共享取消不遗留轨道。

**用户运行验收：**

1. A 共享指定窗口，B 实际观看；系统停止共享后两端回到正常布局。
2. A/B 可各自共享，主画面选择正确，停止一个不影响另一个。
3. 主持人静音 B 后声音停止，B 可自行再开麦；不强制远程开麦。
4. 移出 B 后本场不可重新加入；普通成员不能会控。
5. 主持人个人离开不结束；结束会议则所有人退出且不能再入。

**停点：** 共享和会控通过，才进入会后功能。

### 第 6 阶段：记录、笔记、聊天增强和稳定性

**开发：** 历史列表/筛选/详情、参会区间与时长、手动笔记、未读/发送失败重试、设备热插拔列表/手动切换、响应式优化、限流、自动超时结束、优雅退出和重启恢复。

**Codex 检查：** 历史对象权限、笔记 version 冲突、时长重复累计、消息 ACK 乱序/重试、超时调度、容量竞争、异常 JSON/XSS、关键状态并发测试；Go race 若环境支持。

**用户运行验收：**

1. 结束后能查历史、成员、聊天；未参加账号不能查看。
2. 保存笔记刷新不丢，作者只能编辑自己的笔记。
3. 面板关闭时远端消息增加未读，打开后清零；失败重试不重复。
4. 插拔设备列表更新，设备断开有提示且不擅自开麦。
5. 1440/768/390px 下核心按钮可用；重进/退出/结束后资源正常。

**停点：** 基础及选定进阶稳定后，才添加 AI。

### 第 7 阶段：DeepSeek 纪要与导出

**开发：** Go DeepSeek 适配、配置状态、冻结来源、生成任务/轮询/失败重试、结构校验、查看和 Markdown 导出。记录缺 Key 与上游错误，保护秘密。

**Codex 检查：** mock HTTP 测成功、401/429/超时/空结果/截断/JSON 错误；对象权限、重复生成、来源变更、超限；mock 只证明逻辑，不等于实际生成成功。

**用户运行验收：**

1. 在测试会议聊天和笔记中写明确内容，如“下周三前由小李完成接口文档”。
2. 结束会议，未配置 Key 时按钮说明清楚；配置后由主持人点击生成。
3. 至少一次真实 DeepSeek 返回，纪要准确保留已知事项，不乱编责任人和日期。
4. 所有页面显示仅基于聊天/笔记；没有语音记录不能冒出语音内容。
5. 刷新可查看结果；Markdown 可下载打开；错误配置有清楚提示，不回假结果。

**停点：** 用户确认真实 DeepSeek 生成和导出后再最终验收。Key 从用户已有 DeepSeek 平台账户自行获取，不在聊天/代码中提供。
