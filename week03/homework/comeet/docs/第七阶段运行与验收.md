## 实际实现

入口：历史会议 → 会议记录详情 → DeepSeek 会议纪要。页面始终注明：**“由 DeepSeek 基于聊天与手动笔记生成，不含语音转写，请核对内容。”** 不采集音频、不录音、不做语音转写。

- 仅会议完全 ended 后，主持人才可确认发送本场全部聊天和已保存手动笔记；未保存草稿不在来源中。实际参会者可查看/导出；未参会、仅预留或仅知道会议号的人无权访问。后端每个入口重新鉴权，客户端不能指定作者、上游地址或任意会议来源。
- POST快速返回任务，后台Go net/http调用DeepSeek `/chat/completions`，非流式、JSON输出，无工具、无自动无限重试。状态 running/succeeded/failed 落库；页面轮询、刷新恢复。最多并行2个任务，同场只能1个；每场每分钟最多3个新任务，超限429/Retry-After。
- 冻结本场消息ID/发送者快照/文本与笔记ID/作者/版本，保存快照及SHA-256。相同来源成功结果直接复用，明确重新生成才另发调用；原请求编号和合并到其他任务的编号均持久去重。响应丢失后可用原编号找回任务，不因断开页面取消已接受的任务。
- 后续保存笔记会刷新来源状态；其他标签页修改后，切回页面或点击“刷新纪要状态”会检测更新。旧结果仍对应旧快照，不自动覆盖；新生成失败也保留最近成功结果供查看/导出。任务选择列出最近10次及最近成功记录。
- 服务退出取消后台请求并尽力保存失败；启动将中断任务标记失败，用户明确重试可能再次产生费用。数据库写结果失败不报成功，旧running到超时加15秒宽限后会变成“结果未确认”，重启同样可恢复失败状态；不得据此认定上游没有计费。
- 缺配置、无有效来源不调用模型。超过输入预算明确拒绝，不静默截断、不自动分块。聊天本身超限时本版无法生成全部纪要，可先导出原始记录；缩短笔记仅在笔记造成超限时有效。
- 校验响应结构、finish_reason、空白、截断、JSON、字段/数组长度及来源ID；决策/待办必须引用实际来源。owner/dueDate未知必须null；非null须能在引用原文中找到，日期只接受明确YYYY-MM-DD。页面用React纯文本渲染，不注入模型HTML；Markdown转义HTML和语法元字符。结构校验不能证明模型理解准确，仍需人工核对。
- 导出成功纪要包含模型、生成时间、来源hash、纪要、引用和冻结原记录。未生成或未配置也能导出“会议记录”，不冒称AI输出。原始记录导出单独限制20万字符/100万字节；达到上限明确失败，不静默丢记录。

官方文档 https://api-docs.deepseek.com/ 、JSON模式 https://api-docs.deepseek.com/guides/json_mode/ 在当前云访问返回403，无法确认此刻账户可用模型，所以不写死过往模型名，也不声称所有模型都兼容。请以自己平台控制台/API返回为准。可以在本机读私有.env查询模型列表，仅输出ID（适用于上面普通单行dotenv格式）：

```powershell
cd D:\comeet-stage1-review\week03\homework\comeet\server
$localKeyLine = Get-Content .env | Where-Object { $_ -match '^\s*DEEPSEEK_API_KEY\s*=' } | Select-Object -Last 1
$localDeepSeekKey = ($localKeyLine -split '=', 2)[1].Trim().Trim('"').Trim("'")
try {
    $availableModels = Invoke-RestMethod -Method Get -Uri 'https://api.deepseek.com/models' -Headers @{ Authorization = "Bearer $localDeepSeekKey" }
    $availableModels.data | Select-Object id
} finally {
    Remove-Variable localDeepSeekKey, localKeyLine -ErrorAction SilentlyContinue
}
```

把选定、支持Chat Completions和JSON输出的ID填入DEEPSEEK_MODEL。API地址可配置（支持官方 `/v1` 基址），只接受无用户名/密码/query的HTTPS；本地HTTP仅开发测试。请求不跟随重定向，防止转发Key。系统环境变量优先于.env，改完必须重启Go；切勿把“配置已填写”当成第三方调用已验证。

保守预算不是精确token计数。配置范围：超时1–300秒，输出1–32768 tokens，来源字符1–200000，来源字节1–1000000；还需符合所选模型上下文/输出限制。没有按模型猜测并自动套用temperature或thinking参数。余额/额度/模型参数由实际DeepSeek响应判定。

## 错误处理与诊断

页面失败显示分类、建议及诊断编号。后端只记录 `summary_task_finished/summary_persist_failed` 的task_id、request_id、status、error_code；不打印Key、上游原文、来源或聊天/笔记内容。http_request仍只记录路径/状态，不记录请求体或Authorization。

| 分类 | 本机可操作步骤 |
|---|---|
| AI_NOT_CONFIGURED | 检查私有.env的启用/模型/Key，重启Go；不需要向聊天提供Key |
| SOURCE_EMPTY / SOURCE_TOO_LARGE | 保存有效笔记；核对来源预算，不截断冒充完整总结 |
| AI_AUTH | 在本机核对Key及账户权限，不盲目轮换；不上传.env |
| AI_QUOTA | 在DeepSeek平台检查余额/额度 |
| AI_UPSTREAM_RATE_LIMITED / AI_RATE_LIMITED / AI_BUSY | 等待后手动重试，重复查询不新增任务 |
| AI_TIMEOUT / AI_NETWORK / AI_UNAVAILABLE | 检查运行Go机器到DeepSeek的网络和服务状态；重试可能再产生费用 |
| AI_REQUEST_REJECTED | 核对账户可用模型、JSON模式参数与基址，不自动切换其他服务 |
| AI_EMPTY_RESPONSE / AI_INVALID_RESPONSE / AI_INVALID_RESULT / AI_TRUNCATED | 未算成功；核对输出预算或稍后明确重试 |
| SERVER_RESTART / AI_RESULT_UNCONFIRMED | 结果未确认；先查看持久任务，再明确重试，不承诺上游未计费 |

实际自动检查明细见[阶段验收](阶段验收.md)最新第七阶段记录。

## 真实 DeepSeek 双账号人工验收（待用户执行）

1. 先禁用DeepSeek重启：纪要区域始终注明“不含语音转写”，提示未配置、生成禁用，没有假纪要；原始会议记录可导出。再在私有.env正确配置并重启，页面显示已填写，但不声称已经验证。
2. A主持、B实际入会，聊天写清一项决策、一项含明确负责人/日期的待办，再写一项未指定责任人/日期的待办；A/B保存各自笔记。保留已有音视频/共享/面板行为。未保存草稿不应被发送。结束会议后由A进入历史生成，确认提示说明发送范围及可能费用。
3. 至少一次真实DeepSeek生成成功：状态先生成中、后成功保存；逐项对照聊天/笔记和sourceIds，确认无虚构任务、责任人/日期，未知值为“未明确”，始终注明“不含语音转写”。模型若理解有误应记录为问题，不能以JSON合法替代准确性验收。
4. 生成中连续点击/刷新/离开再返回，仍是同一运行任务；不出现并行同场生成。B可看成功结果但不能生成；未参会C及仅预留者无权读任务/导出。切勿向C分享浏览器登录凭证来测权限。
5. A更新并保存笔记，提示“记录已更新，可重新生成”；旧纪要仍对应旧来源。明确确认后重新生成得到新任务；失败时仍可选择上次成功结果。重复请求/同源成功复用由自动测试覆盖，手动重新生成会明确提示可能收费。
6. 在专用测试环境暂时断开Go到DeepSeek的网络，验证任务失败而非假成功，错误带分类/编号；恢复后明确重试成功。可选降低超时测试超时（可能仍计费），完成后恢复90秒。认证/额度/429/无效返回等已自动覆盖，无需盲目更换Key或耗尽余额来测试。后台Ctrl+C/重启后成功结果仍保留，未完成任务显示中断可重试。
7. A/B导出成功纪要Markdown，核对会议信息、模型/时间、来源hash、冻结聊天与笔记、决策/待办和局限。更新来源后导出旧任务仍是旧快照；原始导出叫“会议记录”。检查1440×900、1366×768和390px下任务选择/错误/导出无横向溢出。记录实际模型ID、日期、浏览器及人工核对结论，不记录Key。
